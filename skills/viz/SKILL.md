> 이 문서의 상대 경로(`../generator/toc.css` 같은 것)는 이 SKILL.md가 있는 폴더 기준이다. 플러그인 루트는 그 두 단계 위다. 셸 명령에서는 절대 경로로 바꿔 쓴다.
>
> **공용 스크립트** `../../scripts/ta.py`(`python3 <절대 경로>/ta.py <cmd> …`). 위치 찾기(`find`), 삽입(`insert`), 공용 조각·`viz.css`·`v3d`(`fragments`), 캡처(`shot`)는 이 스크립트로 한다.

# 역할
글로는 잘 안 잡히는 **구조·흐름·크기 비교**를 한 장의 그림으로 보여 준다. 그림은 장식이 아니라 설명이다. 그림을 본 독자가 본문 한 문단을 안 읽고도 "아, 이런 모양이구나" 해야 한다.

대상 독자는 `../generator/SKILL.md`의 `# 학습자 정보`, 말투는 같은 파일의 `# 말투`를 따른다.

# 언제 그리나
- 그린다:
  - 구조(무엇이 무엇 안에·옆에 있는지): Transformer 층 안에서 adapter가 끼는 자리, Model 위의 Head.
  - 흐름(무엇이 무엇으로 바뀌는지): pre-training → copy → fine-tuning.
  - 크기·양 비교: 행렬 모양(4096×4096 vs 4096×8), parameter 수 막대.
- 그리지 않는다:
  - 원자료에 같은 그림이 이미 있으면 → "원자료 해설"로 그 그림을 가져와 해설한다. 다시 그리지 않는다.
  - 표로 충분한 비교(방법 A/B의 장단점) → 표.
  - 글 한 줄로 끝나는 내용.
- 그림 하나 = 핵심 하나. 한 그림에 두 가지 이야기를 넣지 않는다.

# 형식
- **인라인 SVG**가 기본. 외부 이미지·라이브러리 없이 HTML 안에 그대로 넣는다. 상자·화살표만으로 되는 흐름도는 HTML/CSS(flex·grid)로 그려도 된다. 깊이·부피·쌓임이 핵심이면 아래 "# 3D"를 따른다.
- 블록 마크업. 번호는 ①②③…, `id`는 `viz1, viz2, …`.
  ```html
  <div class="viz" id="viz1">
  <h4>시각화 ① Transfer learning 2단계와 Head 교체</h4>
  <svg viewBox="0 0 720 260" role="img" aria-label="pre-training과 fine-tuning 흐름">…</svg>
  <p class="viz-leg"><span class="sw sw-fix"></span>고정(freeze) <span class="sw sw-new"></span>새로 학습</p>
  <p class="src">7_TransferLearning.pdf p.9–10, p.17–18 기반 재구성</p>
  </div>
  ```
- **SVG 규칙**
  - `viewBox`만 쓰고 `width`/`height` 속성은 쓰지 않는다(CSS가 폭 100%로 맞춘다). 가로 720 안팎, 세로는 내용만큼. 세로로 긴 그림은 피한다.
  - 색은 직접 적지 않고 아래 `viz.css`의 클래스를 쓴다: 상자 `bx`(일반), `bx-fix`(고정·공유되는 것), `bx-new`(새로 학습·추가되는 것), `bx-soft`(배경 묶음), 선 `ln`, 점선 `ln-dash`, 화살표 `marker-end="url(#ah)"`, 작은 설명 글자 `cap`. 라이트/다크 모드는 CSS 변수가 맞춘다. `fill="#fff"`처럼 색을 박아 넣지 않는다.
  - 글자는 `<text>`로, 크기 12 이상, 상자 안 글자는 `text-anchor="middle"`. 용어는 본문과 같은 영어 원어(Model, Head, adapter).
  - 화살표 marker는 그림마다 `<defs>`에 넣는다(id는 `ah`로 통일. 한 문서에 여러 그림이 있어도 같은 모양이므로 충돌해도 문제없다).
  - 수식·첨자가 필요하면 그림 안에는 짧은 기호만 쓰고(W, ΔW, r), 뜻은 범례나 본문에서 푼다.
- **범례** `<p class="viz-leg">`: 색을 두 가지 이상 쓰면 반드시 넣는다. 색만으로 구분하지 않는다(상자 라벨에도 "frozen", "new"를 적는다).
- **출처** `<p class="src">`: 원자료의 어느 페이지를 바탕으로 재구성했는지 적는다("p.N 기반 재구성"). 원자료 없이 일반 지식으로 그렸으면 "(자료 외 보충)". 배지는 왼쪽 페이지 색인에 잡히지만, 시각화 섹션은 `data-noidx`라 강조되지는 않는다.
- **해설**: 그림만으로 부족하면 아래에 `ul.pts`(굵은 소제목 + 설명)로 각 부분의 뜻을 쓴다. 그림이 자명하면 생략한다.
- **상호 참조**: 그림이 보여 주는 장면의 숫자가 예시에 있으면 "수치는 `<a href="#ex9">예시 ⑨</a>` 참고"처럼 잇는다. 본문에서 그림을 가리킬 때는 `<a href="#viz1">시각화 ①</a>`.
- **CSS는 한 번만**: `viz.css`는 문서에 `.viz` 블록이 있으면 `ta.py fragments <파일>`이 `</style>` 앞에 넣는다(마커 `/*ta-viz:start v1*/`, 구버전이면 교체). 문서 CSS에서 `.viz`를 따로 정의하지 않는다.

# 3D (필요할 때만)
기본은 2D(SVG)다. **깊이·부피·쌓임·회전이 이해의 핵심**일 때만 3D로 그린다.
- 3D로 그린다:
  - 감기거나 펼쳐지는 것: 롤을 펼쳐 넓이가 되는 과정, 관·원통의 단면과 길이.
  - 쌓임·부피: 팔레트 적재, 3축 텐서(배치 × 길이 × 차원), 합성곱 필터가 3차원 입력을 훑는 모습.
  - 3차원 공간의 기하: 곡면 z = f(x, y)와 경사하강 경로, 3차원 점구름과 결정 경계, 벡터의 사영.
  - 같은 물체 위에서 이어지는 여러 단계: "하나 → 여러 개 → 무게"처럼 한 장면을 단계 버튼으로 넘겨 볼 때.
- 3D로 그리지 않는다: 상자·화살표 흐름도, 막대 비교, 표로 되는 것, 평면 그림으로 충분한 것. 3D는 파일을 약 600KB 키우므로 문서당 1~2개까지만 쓴다.

## 구성
- 3D 그림도 `.viz` 블록 하나다. 번호·`id`·`h4`·범례·출처 규칙은 2D와 같고, 제목 끝에 "(3D)"를 붙인다.
- **2D 대체 그림을 반드시 `.v3d-fb`에 함께 넣는다.** WebGL이 안 되는 환경과 인쇄에서는 이 그림이 보인다.
- 장면 정의는 블록 **바로 뒤** `<script>`에 `TA3D_Q.push({...})`로 쓴다. three.js 엔진과 공통 동작(단계 버튼, 단계 사이 애니메이션, 카메라 이동, 드래그 회전, 라벨, 라이트/다크, 화면 밖에서 멈춤, 동작 줄이기 설정)은 공용 조각 `v3d.html`·`v3d.css`가 맡는다. `ta.py fragments`가 문서에 `class="v3d"`가 있으면 넣고, 없어지면 뺀다. 손으로 붙이지 않는다.

```html
<div class="viz" id="viz3">
<h4>시각화 ③ 롤 48개가 1,804.8kg이 되기까지 (3D)</h4>
<div class="v3d" data-label="롤 하나를 펼쳐 넓이를 구하고, 48롤로 모은 뒤 무게를 구하는 3D 장면"></div>
<div class="v3d-fb" hidden><svg viewBox="0 0 720 300" role="img" aria-label="…">…2D 그림…</svg></div>
<p class="viz-leg">…</p>
<p class="src">p.8 기반 재구성 · 길이 400m만 줄여서 그림</p>
</div>
<script>
(window.TA3D_Q=window.TA3D_Q||[]).push({
  id:'viz3',                          // 위 .viz의 id
  vars:{p1:0,p2:0,p3:0},              // 단계 사이를 부드럽게 오가는 변수(0~1 권장)
  steps:[                             // 버튼 하나 = 단계 하나. 2~4단계
    {label:'① 롤 1개 펼치기', goal:{p1:1,p2:0,p3:0}, cam:{p:[6,5,14],t:[0,0,4]}, say:'이 단계에서 볼 것 한 문장'},
    …
  ],
  labels:[                            // 3D 위치에 붙는 HTML 라벨
    {t:'W = 2.35m', c:'t1', at:(v,s)=>[0,0.05,-0.8], on:(v,s)=>s===0}
  ],
  build({T,scene,color,ease,clamp}){  // 물체를 scene에 넣고, 매 프레임 부를 함수를 돌려준다
    const m=new T.Mesh(new T.BoxGeometry(1,1,1), color(new T.MeshStandardMaterial(),'--accent'));
    scene.add(m);
    return (v,dt,step)=>{ m.position.y=v.p1; };
  }
});
</script>
```

- **steps**: `goal`에는 **모든 변수의 목표값**을 적는다(어느 단계로 바로 가도 장면이 맞도록). `cam.p`는 카메라 위치, `cam.t`는 바라보는 점. `say`는 버튼 아래에 뜨는 한 문장 설명이다(`# 말투`).
- **labels**: `c`는 색 클래스. 수식 항과 짝지을 때 `t1`~`t5`(`math`의 항 색과 같음), 그 밖에 `new`(새로 추가)·`fix`(강조)·빈 값(기본 글자색). `at`은 3D 좌표, `on`은 보일 조건. 글자는 짧게(기호 = 값).
- **build(ctx)**: `ctx.T`가 three.js다(`T.Mesh`, `T.BoxGeometry`, `T.CylinderGeometry`, `T.InstancedMesh`, `T.MeshStandardMaterial` 등, 전체 목록은 `3d/entry.js`). 조명과 그림자 받는 바닥은 런타임이 깐다.
- **색**: 의미가 있는 색은 `color(재질, '--변수')`로 CSS 변수에 묶는다(`--accent`, `--viz-new`, `--t1`~`--t5`, `--muted`). 라이트/다크 전환 때 다시 칠해진다. 실제 물체의 고유색(흰 부직포, 갈색 종이관)만 숫자로 적는다.
- **비율**: 실제 비율을 지키되, 화면에 안 들어가는 축만 줄이고 출처 줄과 라벨에 "줄여서 그림"을 적는다.
- 같은 모양이 수십 개 이상이면 `T.InstancedMesh`를 쓴다.
- 선택 옵션: `hint`(조작 안내 문구), `dur`(단계 전환 초, 기본 1.6), `shadow`(그림자 범위, 기본 10), `ground:false`(바닥 끄기).
- 엔진에 없는 three.js 클래스가 필요하면 `3d/entry.js`에 더하고 저장소 루트에서 `npm run build:v3d`로 `v3d.html`을 다시 만든다. 이때 `3d/build.mjs`의 `VERSION`을 올린다.

## 3D 점검
- 단계마다 찍는다: `ta.py shot <학습자료> --id vizN --step 0`, `--step 1`, …(0부터), 다크는 `--dark`, 모바일은 `--width 400`. 3D가 있으면 `shot`이 런타임과 장면 정의를 함께 넣고 소프트웨어 WebGL로 그린다. 문서에 넣기 전이면 `--snippet`에 `.viz` 블록과 장면 정의 `<script>`를 함께 담는다.
- 볼 것: 2D 점검 항목에 더해, 라벨이 물체와 겹쳐 읽기 어렵지 않은지, 단계마다 카메라가 핵심 물체를 화면 가운데에 담는지, 모바일 폭에서 물체가 너무 작지 않은지.
- `.v3d-fb`의 2D 그림도 아래 "# 작성 후 점검"대로 본다.

# 작성 후 점검
- 그림을 문서 CSS와 함께 헤드리스 Chrome으로 라이트·다크 두 번 캡처해 직접 본다. Chrome이 없으면 스크립트가 건너뛴다고 알린다(`TA_CHROME` 환경변수로 경로 지정 가능).
  ```bash
  python3 <ta.py> shot <학습자료.html> --id vizN --out <scratch>/vizN.png
  python3 <ta.py> shot <학습자료.html> --id vizN --dark --out <scratch>/vizN-dark.png
  python3 <ta.py> shot <학습자료.html> --id vizN --width 400 --out <scratch>/vizN-m.png   # 모바일 폭
  ```
  아직 문서에 넣기 전이면 `--snippet <조각.html>`로 조각 파일을 대신 준다(문서 CSS는 `<학습자료.html>`에서 가져온다).
- 볼 것: 글자가 상자 밖으로 나가거나 겹치지 않는지, 화살표 방향이 맞는지, 다크 모드에서 글자·선이 보이는지, 모바일 폭에서 글자가 너무 작아지지 않는지(작아지면 그림을 둘로 나눈다).
- 그림이 본문의 어떤 문장을 보여 주는지 한 문장으로 말할 수 있어야 한다. 말할 수 없으면 뺀다.

# 다른 ta 스킬에서 쓸 때
- **`generator`**: "시각화" 섹션(`<h2 data-noidx>`, 보통 `2.`)에 모아 넣는다. 개념 설명 바로 옆에 두는 것이 훨씬 이해에 도움이 되면 그 자리에 넣어도 된다. 시각화가 하나도 필요 없으면 섹션을 만들지 않고 번호를 당긴다.
- **`research`**: 웹 이미지를 그대로 넣지 않는다. 핵심 도식은 이 규칙대로 다시 그리고 출처에 "[N]의 그림을 다시 그림"을 적는다.
- **`supplement`·`example`**: 보충·추가 예시 블록 안에 작은 그림이 도움이 되면 같은 마크업으로 넣는다(`id`는 `viz-sup-N`, `viz-exm-N`). 블록이 접혀 있을 때는 그림도 함께 접힌다.
- **`quiz`**: 문항에 그림이 필요하면 같은 마크업을 쓰되 `viz.css`를 퀴즈 파일에도 복사한다. 퀴즈에는 3D를 쓰지 않는다(2D만).

# 직접 호출했을 때 (기존 학습자료에 시각화 덧붙이기)
1. **위치 찾기** — `ta.py find <학습자료> "<복사한 부분>" --json`(`supplement`의 "위치 찾기"와 같다. HTML 전체를 Read로 읽지 않는다). 학습자료 경로가 없으면 `ta.py config`의 `out_dir`에서 최근 수정된 `*<suffix_notes>*.html`.
2. **무엇을 그릴지** — 그 부분이 말하는 구조·흐름·비교 중 그림으로 가장 잘 보이는 하나를 고른다. 이미 같은 내용의 `.viz`나 원자료 그림이 있으면 새로 그리지 않고 그 위치로 링크만 단다고 알린다. 2D로 할지 3D로 할지는 "# 3D"의 기준으로 정한다. 사용자가 "3D로"라고 하면 3D로 그린다. 기존 2D 그림을 3D로 바꿀 때는 그 2D 그림을 `.v3d-fb`로 옮겨 대체 그림으로 쓴다.
3. **근거 확인** — 원자료에서 관련 페이지를 찾아 모양·숫자가 어긋나지 않는지 확인한다. `research` 문서면 `<out_dir>/.sources/<주제>/`를 쓴다.
4. **그리기** — 위 "# 형식"대로. 번호는 문서의 마지막 시각화 다음 번호, `id`는 `vizN`. 조각을 파일로 써 두고 `shot --snippet`으로 먼저 본다.
5. **삽입** — 문서에 시각화 섹션이 있으면 그 끝(`ta.py insert --after <마지막 .viz의 #id>`)에, 없으면 대상 블록 바로 뒤(`--after <find의 block.end>`)에 넣는다(`insert`가 `.backup/`에 원본을 남긴다). 대상 문장 끝에 `<a href="#vizN">시각화 N</a>` 링크를 단다. `ta.py fragments <학습자료>`로 `viz.css`와 공용 조각을 맞춘다. 원래 문장은 고치지 않는다.
6. **점검·열기** — "# 작성 후 점검"을 한 뒤 `open "file://<URL 인코딩한 절대경로>#vizN"`으로 연다. 응답에는 파일 경로와 그린 내용 한 줄만 적는다.
