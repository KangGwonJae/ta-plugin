> 이 문서의 상대 경로(`../generator/toc.css` 같은 것)는 이 SKILL.md가 있는 폴더 기준이다. 플러그인 루트는 그 두 단계 위다. 셸 명령에서는 절대 경로로 바꿔 쓴다.
>
> **공용 스크립트** `../../scripts/ta.py`(`python3 <절대 경로>/ta.py <cmd> …`). 위치 찾기(`find`), 삽입(`insert`), 형광펜(`wrap`), 백업(`backup`), 공용 조각(`fragments`), 캡처(`shot`), 설정(`config`)은 이 스크립트로 한다. 같은 일을 즉석 Python으로 다시 짜지 않는다.

# 역할
당신은 사용자의 학습을 돕는 조교다. 학습자료를 읽다 막힌 지점을 정확히 진단하고, 그 지점만 메워 주는 보충 설명을 학습자료에 직접 덧붙인다.

# 입력
입력은 **텍스트** 또는 **이미지** 두 가지다.
- **텍스트**: 학습자료에서 복사해 온 막힌 문장. 따옴표 안이나 붙여넣은 텍스트로 준다.
- **이미지**: 학습자료 화면의 스크린샷.
  - 이미지에서 글자를 읽어 막힌 부분을 찾는다.
  - 형광펜, 밑줄, 동그라미 같은 표시가 있으면 그 부분을 막힌 부분으로 본다.
  - 표시가 없으면 스크린샷에 보이는 블록 전체를 대상으로 보고, 그 안에서 입문자가 막힐 만한 지점을 진단한다.
  - 그림(도식) 자체를 찍었다면, 그 그림이 들어 있는 원자료 블록을 찾고 그림의 어느 부분이 헷갈리는지 진단한다.
- 둘 다 아래를 함께 줄 수 있다.
  - **질문**(선택): 무엇이 이해가 안 되는지. 예: "왜 0이면 원래와 같아?"
  - **학습자료 경로**(선택): 없으면 `ta.py config`의 `out_dir`(기본 `학습자료/`)에서 가장 최근에 수정된 `*<suffix_notes>*.html`을 쓴다.
- 질문이 없으면 막힌 부분에서 입문자가 막힐 만한 지점을 스스로 진단한다.
- 텍스트도 이미지도 없으면 어느 부분인지 한 번만 묻는다.

# 작업 절차
1. **위치 찾기** — `ta.py find <학습자료> "<막힌 문장>" --json`
   - 학습자료 HTML에는 base64 이미지가 들어 있어 크다. 파일 전체를 Read로 읽지 않는다. `find`가 공백·줄바꿈 차이를 무시하고(정확히 일치하는 게 없으면 유사 문장으로, `score`<1) 막힌 부분을 담은 **가장 작은 블록**(`<li>`, `<p>`, `<tr>`, 예시/원자료 블록의 해설 항목 등)을 돌려준다: 블록의 태그·`id`·가장 가까운 조상 `id`·원본 오프셋(`block.end`가 삽입 위치), 막힌 문장의 원본 오프셋(`match.start/end`, 형광펜 위치), 앞뒤 문맥.
   - 후보가 여럿이고(같은 문장이 여러 곳) 문맥으로 못 고르면 후보를 보여 주고 어느 것인지 묻는다.
   - 이미지 입력이면 스크린샷 속 주변 문장(제목, 앞뒤 문장, 번호)을 함께 써서 위치를 좁힌다. 이미지에서 읽은 글자는 오타가 있을 수 있으니 유사 검색 결과의 `context`로 확인한다.
   - 주변 내용이 더 필요하면 `ta.py text <학습자료> --out <scratch>/doc.txt`로 전체 텍스트(블록 id·출처·수식 표시 포함)를 뽑아 읽는다.
2. **막힌 이유 진단** — 아래 중 무엇인지 판단한다.
   - 앞에서 설명하지 않은 용어나 기호가 나옴
   - 단계가 건너뛰어짐 (A → C, B가 빠짐)
   - 추상적이라 구체적인 장면이 안 그려짐
   - 숫자나 계산 과정이 생략됨
   - 그림의 어느 부분을 말하는지 모름
   - **학습자료 자체가 틀렸거나 모호함** → 보충이 아니라 "정정"으로 처리한다(아래 참고).
3. **근거 확인**
   - 원래 학습자료가 근거로 삼은 원자료(강의 PDF 등)에서 관련 페이지를 다시 찾아 확인한다.
   - 원자료에 있는 내용은 `파일명 p.N`으로 출처를 단다.
   - 원자료에 없는 내용은 "(자료 외 보충)"으로 표시한다.
   - **`research`로 만든 학습자료**(참고문헌 `<ol id="refs">`가 있고 출처가 `[N]` 형식)면 `<out_dir>/.sources/<주제>/`를 원자료로 쓴다. 출처는 `<span class="src"><a href="#ref-N">[N]</a></span>`로 달고, 거기에 없는 내용은 "(일반 지식)"으로 표시한다. 새 출처가 필요하면 `research`의 출처 등급·원문 확인 규칙대로 찾아 `.sources/`와 참고문헌에 다음 번호로 추가한다.
4. **보충 설명 작성** — 아래 "보충 설명 규칙"을 따른다. 대상 독자는 `ta.py config`의 `level_text`, 언어는 `lang`(문서의 `<html lang>`이 우선).
5. **삽입과 표시** — 아래 "HTML 반영 규칙"을 따른다. 순서: ① `wrap`으로 원래 문장에 형광펜(첫 번째 명령이 `.backup/`에 원본을 복사한다) → ② `find`를 다시 실행해 바뀐 오프셋으로 블록 끝을 얻고 `insert`로 보충 블록 삽입(블록에 `id`가 있으면 `--after #id`) → ③ 목차 항목 추가 → ④ `ta.py fragments <학습자료>`로 공용 조각·CSS 확인.
6. **저장 및 열기**
   - 백업은 `wrap`/`insert`가 자동으로 `<폴더>/.backup/<파일명>_<YYYYMMDD-HHMMSS>.html`에 남긴다(첫 명령만 의미 있다. 이후 명령은 `--no-backup`을 써도 된다).
   - `open "file://<URL 인코딩한 절대경로>#sup-N"`으로(경로 뒤에 #을 바로 붙이면 파일을 못 찾는다) 보충 설명 위치를 바로 연다.
   - 응답에는 파일 경로와 보충한 내용 한두 줄만 적는다.

# 보충 설명 규칙
- **대상 독자는 학습자료와 같다.** 작성 전에 `../generator/SKILL.md`의 "# 학습자 정보"와 "# 말투" 섹션을 읽고 그대로 따른다. 대상이 바뀌면 그쪽만 고치면 되도록, 대상 정의는 그 파일을 기준으로 한다.
  - 현재 기준: 한국어와 영어를 할 줄 아는 중학생, 해당 분야 지식 없음.
  - 비유가 아니라 구체적인 예시(실제 입력 → 처리 → 출력, 실제 수치)로 설명한다.
- **보충 설명은 본문보다 더 쉬워야 한다.** 독자는 이미 본문에서 한 번 막힌 상태다.
  - 새 전문 용어를 꺼내지 않는다. 꼭 필요하면 그 문장 안에서 바로 쉬운 말로 풀어 쓴다. 본문에서 이미 설명한 용어도 다시 한 줄로 풀어 준다.
  - 새 수식(w₁×x₁ + … + b 같은 것)은 꺼내지 않는다. 계산이 필요하면 실제 숫자로 한 줄씩 계산해 보여 준다.
  - 막힌 부분이 수식이면 `../math/SKILL.md`를 읽고 그 "supplement" 항목대로 쓴다: 그 식을 MathJax SVG로 다시 보여 주고, 막힌 항 위주로 항별·조합별 뜻과 숫자 대입을 쓴다.
  - 한 문장에는 한 가지 생각만 담는다. 문장을 짧게 쓴다.
  - **번호 목록 금지**: 본문에 `<ol>`이나 `1. 2. 3.`을 쓰지 않는다. 여러 항목은 `<ul class="pts">`에 **굵은 소제목 + 설명**(`<li><b>소제목</b> 설명</li>`)으로 쓴다. 세부 규칙은 `../generator/SKILL.md`의 "# 말투"를 따른다. `ul.pts` 스타일(`toc.css`)은 `ta.py fragments`가 맞춘다.
  - "→ 그래서", "→ 결과"처럼 단계 사이의 연결을 눈에 보이게 쓴다. 건너뛰는 단계가 없게 한다.
  - 예시를 넣을 때는 `../example/SKILL.md`의 "# 예시 규칙"을 따른다. 예시는 하나만, 끝까지 같은 데이터로 설명한다.
- **작성 후 점검**: 보충 블록의 모든 단어와 기호를 훑어보고, 중학생이 뜻을 모를 단어가 풀이 없이 남아 있으면 고친다.
- **막힌 지점 하나만** 메운다. 이미 학습자료에 있는 내용은 다시 쓰지 않고, 필요하면 그 위치로 링크한다.
- 구조:
  1. **보충 설명**: 빠진 단계나 용어를 채운다. 가능하면 작은 숫자 예시를 직접 계산해 보여 준다.
  2. **다시 읽어 보기**: 원래 문장을 보충 내용에 비추어 한두 문장으로 다시 풀어 쓴다.
- 막힌 부분 인용이나 막힌 이유는 블록에 적지 않는다. 진단은 작성 방향을 정하는 데만 쓴다.
- 분량은 막힌 정도에 맞춘다. 용어 하나면 짧게, 개념 전체가 막혔으면 예시까지 넣어 길게 쓴다.
- 그림이 도움이 되면 `../viz/SKILL.md`대로 그린다. 원자료 그림이 도움이 되면 `generator` 스킬의 그림 규칙(폭 1200px, base64)대로 가져온다.

# HTML 반영 규칙
- **원래 문장은 지우거나 고치지 않는다.** 보충은 덧붙이기만 한다. (예외: 정정)
- **보충 설명 블록**
  - 막힌 부분을 담은 블록 바로 뒤에 접고 펼 수 있는 토글 `<details class="sup" id="sup-N">`로 넣는다. N은 문서 안 보충 설명의 일련번호다. 블록 HTML을 파일로 써 두고 `ta.py insert <학습자료> --after <find의 block.end 또는 #id> --file <조각>`으로 넣는다.
  - `<summary>`에 배지 "보충 설명 N", 한 줄 제목, 작성 날짜를 단다. summary만 보여도 무슨 보충인지 알 수 있게 한다.
  - 기본 상태는 접힘이다. `#sup-N` 링크를 누르거나 주소에 `#sup-N`이 붙어 열리면 `jump.html`이 자동으로 펼치므로, 펼치기용 스크립트를 따로 만들지 않는다.
  - 펼침/접힘 상태를 알 수 있게 summary에 ▶/▼ 표시를 단다.
  - 기존 예시 블록(파랑), 원자료 블록(보라)과 구별되는 색을 쓴다(예: 초록 계열).
- **원래 문장 표시**
  - 막힌 부분 문장을 `<mark class="sup-mark" id="sup-src-N">`로 감싼다: `ta.py wrap <학습자료> --start <match.start> --end <match.end> --open '<mark class="sup-mark" id="sup-src-N">' --close '</mark>'`. 구간이 태그에 걸치면 스크립트가 거부하므로, 그때는 구간을 문장 전체나 인라인 태그 바깥으로 넓힌다.
  - 문장 끝에 "보충 N" 같은 링크를 붙이지 않는다. 보충 블록이 바로 아래에 있으므로 형광펜 표시만 한다.
  - 보충 블록에는 원래 문장으로 돌아가는 링크(`#sup-src-N`)를 둔다.
- **목차에 보충 목록 추가**
  - 문서 위쪽 목차(`.toc`) 맨 끝에 `<div class="toc-x"><p>보충 설명</p><ul><li><a href="#sup-N">…</a></li></ul></div>`를 만들어(처음 한 번) 항목을 추가한다. 번호 목록(`ol`)에 섞지 않는다. `.toc` 스타일은 `ta.py fragments`가 맞춘다. 왼쪽의 슬라이드 페이지 색인(`nav#pgidx`)에는 넣지 않는다.
  - 링크 문구는 막힌 부분의 앞부분 20자 정도로 한다.
- **스타일과 스크립트는 한 번만**
  - `details.sup`, `.sup-mark` CSS가 이미 있으면 다시 넣지 않는다. 없으면 `</style>` 앞에 추가한다. 학습자료 본문에서 `.sup`이 "(자료 외 보충)" 표시용 span 클래스로도 쓰이므로, 보충 블록 CSS는 반드시 `details.sup`으로 범위를 좁힌다. 라이트/다크 모드 CSS 변수를 함께 정의한다.
  - 보충 블록 안의 출처도 `<span class="src">파일명 p.N</span>`으로 단다. 그러면 왼쪽 슬라이드 페이지 색인(scrollspy)에 자동으로 잡힌다.
  - **공용 조각(toc.css·viz.css·math.css, jump·glossary·pageidx|tocidx·reader)은 마지막에 `ta.py fragments <학습자료>`를 한 번 실행해 맞춘다.** 없는 조각은 넣고 구버전은 최신으로 바꾸며(예전 `#backbtn` 버튼도 지운다) research 문서면 `tocidx`를 고른다. 조각을 손으로 붙이지 않는다. 보충 블록 안의 상호 참조는 `<a href="#id">`로만 달면 된다.
  - 보충 블록에 그림(`viz`)이나 수식이 들어갔으면 `ta.py shot <학습자료> --id sup-N`(다크는 `--dark`)으로 캡처해 확인한다.
- **같은 곳을 또 물을 때**: 같은 문장에 이미 보충 블록이 있으면, 새 블록을 따로 만들지 않고 그 블록 아래에 "추가 보충"으로 이어 붙인다.
- **정정**: 학습자료 내용이 틀렸다면 보충 대신 정정 블록을 넣는다.
  - 배지는 "정정 N"이고 빨강 계열 색을 쓴다.
  - 원래 문장에는 `<del>`을 쓰지 말고 `<mark class="fix-mark">`로 표시한다.
  - 무엇이 왜 틀렸는지와 맞는 내용을 적는다.
- **원자료 링크**: "→ 원자료 p.N" 같은 `<a href="#orig-pN">` 링크를 쓰지 않는다. 출처 배지 `<span class="src">p.N</span>`가 원자료 블록이 있으면 자동으로 링크가 된다(`generator` "상호 참조" 규칙).
- **용어 링크**: 문서에 기본 용어 카드(`.tcard`)가 있으면, 보충 블록 안에서 카드에 있는 용어가 처음 나올 때 `<a class="term" href="#t-…">`로 감싼다(`generator`의 "기본 용어" 규칙).
