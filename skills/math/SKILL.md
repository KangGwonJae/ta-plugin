> 이 문서의 상대 경로(`../generator/toc.css` 같은 것)는 이 SKILL.md가 있는 폴더 기준이다. 플러그인 루트는 그 두 단계 위다. 셸 명령에서는 절대 경로로 바꿔 쓴다.
>
> **공용 스크립트** `../../scripts/ta.py`(`python3 <절대 경로>/ta.py <cmd> …`). 수식 후보 찾기(`mathscan`), 공용 조각·`math.css`(`fragments`), 캡처(`shot`), 백업(`backup`)은 이 스크립트로 한다. LaTeX→SVG 변환은 이 폴더의 `tex2svg.js`.

# 역할
수식을 교과서처럼 보이게 넣고, 독자가 식을 **말로 읽을 수 있게** 만든다. 식을 보여 주는 것만으로는 부족하다. 식의 각 조각이 무엇을 세거나 재는지, 조각들이 합쳐지면 무슨 뜻이 되는지를 차례로 쌓아 올려 설명한다.

대상 독자는 `../generator/SKILL.md`의 `# 학습자 정보`, 말투는 같은 파일의 `# 말투`를 따른다.

# 무엇이 수식인가
- 수식으로 쓴다: 첨자·위첨자가 붙은 기호(λ_p, a_ip, x²), Σ·∏·분수·루트, 부등식·등식 관계, 함수식(f(x), max, min), 벡터·행렬 표기. 문장 속에 혼자 나오는 기호도 포함한다.
- 수식으로 쓰지 않는다: 문장 속 단순 숫자 계산(1200 + 1100 = 2300), 단위, 코드. 이것들은 일반 텍스트나 `<code>`로 둔다.

# 표기 규칙
1. **LaTeX로 쓰고 MathJax SVG로 변환한다.** HTML `<sub>`/`<sup>`, 유니코드 Σ·λ·≤, monospace 정렬로 수식을 흉내 내지 않는다. SVG를 손으로 쓰지 않는다.
   ```bash
   T="<이 SKILL.md가 있는 폴더의 절대 경로>/tex2svg.js"
   node "$T" '\lambda_p'                                  # 문장 속(inline)
   node "$T" --display '\sum_{p} a_{ip}\,\lambda_p \ge b_i'  # 단독 줄(display)
   printf '%s' '[{"tex":"a_{ip}"},{"tex":"\\sum_p \\lambda_p","display":true}]' | node "$T" --json  # 여러 개
   ```
   - 결과는 `<span class="m" data-tex="…" role="img" aria-label="…"><svg>…</svg></span>`. 글자색이 `currentColor`라 라이트/다크 모드를 따라간다.
   - LaTeX에 오류가 있으면 exit 1과 한 줄 오류를 낸다. 고쳐서 다시 돌린다.
   - 여러 개를 JSON으로 넘길 때 셸 `echo`를 쓰지 않는다(zsh가 `\f` 등을 제어문자로 바꾼다). `printf '%s'`나 Python `subprocess`로 넘긴다.
   - MathJax가 없으면(`node_modules` 없음) `cd "<플러그인 루트: 이 SKILL.md 폴더의 두 단계 위>" && npm install`(거기에 package.json이 있다).
2. **한국어는 수식 밖에 둔다.** `\text{한글}`은 쓰지 않는다. 라벨·설명은 옆 HTML 칸에 쓴다.
3. **Σ의 범위는 아래에 단다.** display에서는 기본으로, 표 칸 안에서는 `\displaystyle`를 붙인다. 곱셈 기호가 생략된 곱은 `\,`로 살짝 띄운다(`a_{ip}\,\lambda_p`).
4. **여러 줄 모형**(목적식 + 제약식들)은 3열 그리드로 쓴다: 라벨 | 수식 | 한 줄 뜻.
   ```html
   <div class="tldr eq" role="group" aria-label="모형 이름">
   <div class="eq-lab">최소화</div><div class="eq-m">{SVG}</div><div class="eq-d">쓰는 롤 수</div>
   ...
   </div>
   ```
5. **CSS는 한 번만 넣는다.** `math.css`(마커 `/*ta-math:start v1*/`)는 문서에 `class="m"` 수식이 있으면 `ta.py fragments <파일>`이 `</style>` 앞에 넣고 구버전이면 교체한다. 손으로 붙이지 않는다.
6. **색으로 항 짝짓기와 강조(기본).** 식 안의 항을 `\class{t1}{…}`~`\class{t5}{…}`로 감싸고, 설명 표에서 그 항을 이루는 행 전부(개별 기호 행과 조합 행)에 같은 `class="t1"`을 단다. 그러면 식의 항과 표의 행이 같은 색으로 이어지고, 표의 줄이나 식의 항에 마우스를 올리거나 누르면 같은 항이 함께 강조되며 나머지는 흐려진다.
   - **뜯어보기 표(`table.eqx`)가 있는 display 식에는 항상 이 짝짓기를 한다.** 스크립트(`eqlink.html`)와 안내 문장은 `ta.py fragments`가 자동으로 넣는다.
   - **표는 식 바로 다음 형제 요소로 둔다.** 사이에 문단을 넣지 않는다. 가로 스크롤용 `<div class="tw">`로 감싸는 것은 괜찮다.
   - 한 식에 최대 5색. 색만으로 구분하지 않는다. 표 첫 칸에 그 부분식 SVG를 함께 둔다.
   - `\class`는 같은 식의 첫 등장(display)에만 쓴다. 문장 속 inline 기호에는 색을 넣지 않는다.
7. **그림과 연동.** 식을 그림으로 보여 주는 시각화가 있으면 그 `.viz`에 `data-eq="eqx-N"`을 달고, 그림 안에서 각 항에 해당하는 요소에 `data-t="tN"`을 단다(`../viz/SKILL.md` "## 수식과 연동"). 그러면 6번의 강조에 그림의 같은 부분도 함께 묶인다. 식·표 강조는 그림이 없어도 동작한다.

# 설명 규칙
수식 하나를 이 순서로 설명한다. 짧은 inline 기호는 ①과 ③의 기호 행만 쓴다.

**① 먼저 말로** — 식 바로 앞에 이 식이 무엇을 구하거나 무엇을 제한하는지 한 문장으로 적는다. 독자가 식을 보기 전에 무엇을 찾아야 하는지 안다.

**② 식** — display 수식. 항마다 `\class{tN}`으로 색을 단다.

**③ 식 뜯어보기 표** — 각 기호 → 기호를 묶은 항 → 항의 조합 → 관계·목표 순서로, **안쪽에서 바깥쪽으로** 쌓는다.
```html
<table class="eqx">
<tr><th>부분</th><th>뜻</th><th>예시 ①에서</th></tr>
<tr class="t2"><td>{a_ip SVG}</td><td>pattern p 하나에 폭 i 조각이 몇 개 들어가는지 (개)</td><td>"1200·1200·1100"의 폭 1200 → 2</td></tr>
<tr class="t3"><td>{λ_p SVG}</td><td>pattern p로 자르는 롤 수 (롤)</td><td>2</td></tr>
<tr class="combo t2"><td>{a_ip λ_p SVG}</td><td>pattern p로 자른 롤들에서 나오는 폭 i 조각 총수 (개). "롤당 개수 × 롤 수"</td><td>2 × 2 = 4</td></tr>
<tr class="combo t1"><td>{Σ_p a_ip λ_p SVG}</td><td>모든 pattern에서 나온 폭 i 조각을 다 더한 것</td><td>4 + 0 = 4</td></tr>
<tr class="combo"><td>{… ≥ b_i SVG}</td><td>그 합이 주문량 이상이어야 한다</td><td>4 ≥ 4 ✓</td></tr>
</table>
```
- 열은 **부분 | 뜻 | 예시 값**. 예시 값은 문서에 이미 있는 예시(가능하면 같은 숫자)로 채운다. 문서에 예시가 없으면 손으로 따라 할 수 있는 작은 숫자를 새로 정한다.
- **뜻 칸에는 무엇을 세는지와 단위를 적는다**(개, 롤, mm, 원, 확률). "계수", "변수"처럼 역할 이름만 적지 않는다.
- **기호의 유래를 뜻 칸 맨 앞에 적는다.** 기호가 처음 풀이될 때 한 번만 쓴다. 표 밖 문장에서 기호를 풀 때도 같다.
  - 영어 단어에서 왔으면 해당 글자를 굵게 한다: `<b>p</b>rice(가격).`
  - 그리스 문자는 이름과 대응하는 글자·단어를 적는다: `Σ(시그마)는 <b>S</b>um(합)의 S에 해당하는 그리스 문자.`
  - 줄임말이 아니면 그렇게 밝힌다: `줄임말 아님. 구할 값에 관습적으로 쓰는 문자.`
  - 유래를 지어내지 않는다. 원자료의 정의나 널리 쓰는 표기를 따르고, 기억을 돕기 위해 문서에서 붙인 단어면 "(자료 외 보충)"으로 표시한다.
- **조합 행**(`class="combo"`)이 이 스킬의 핵심이다. 두 항이 곱해지거나 더해지거나 묶이면, 합쳐진 결과가 무엇인지 새 문장으로 적는다. 연산은 이렇게 읽는다.
  - 곱 → "~당 ~ × ~개 = 총 ~" (단위가 어떻게 바뀌는지 보인다)
  - Σ_k → "k를 하나씩 바꿔 가며 전부 더한다". 무엇을 따라 더하는지(k가 무엇의 번호인지) 적는다.
  - 분수 → "~당 ~", "~ 중 ~의 비율"
  - ≥, ≤, = → "적어도", "넘지 않게", "딱 같게". 왜 그 방향인지 한마디 붙인다(주문은 모자라면 안 되니까 ≥).
  - min/max → "이 값을 가장 작게(크게) 만드는 ~을 고른다". 무엇을 골라서 무엇을 줄이는지 구분한다.
  - 첨자가 식 밖에 남으면(예: Σ_p 뒤에 i가 남음) → "i마다 이런 식이 하나씩 있다(모든 폭에 대해)".
- 앞 행에서 풀지 않은 기호를 뒤 행에서 쓰지 않는다.
- 독자가 처음 보는 연산 기호(Σ, ∏, ∈, ∀, ‖·‖ 등)는 문서에서 처음 나올 때 기호 행 하나로 읽는 법을 적는다.

**④ 숫자 대입** — `<div class="eqcalc">`에 문서 예시 숫자를 식에 그대로 넣어 한 줄씩 계산한다. 계산은 직접 해서 맞는지 확인한다. ③의 예시 값 칸으로 충분히 보이면 생략한다.

**⑤ 다시 읽기** — `<p class="eq-say">`에 식 전체를 한국어 한 문장으로 다시 읽는다. 기호를 쓰지 않고, ③에서 쌓은 뜻을 이어 붙인다.
> 예: "모든 pattern에서 나오는 폭 i 조각을 다 더하면, 그 폭의 주문량 이상이어야 한다. 이 조건이 폭마다 하나씩 있다."

**⑥ 수식 사례** — 뜯어보기 표가 있는 핵심 display 식 바로 아래에 붙인다. 표가 "각 항의 뜻"을 푼다면, 사례는 그 식을 한 장면에 놓아 "이 숫자들이 합쳐져 무슨 뜻이 되는지"를 보여 준다. 아래 "## 수식 사례"를 따른다.

**⑦ 왜 이 모양인지 (선택)** — 모양을 바꾸면 무엇이 달라지는지 보여 주는 것이 이해에 도움이 될 때만 쓴다(≥를 =로 바꾸면 정확히 맞는 조합이 없을 때 풀 수 없다 등).

## 수식 사례
수식 설명 전용 블록이다. `../example/SKILL.md`의 `.ex` 블록(세 부분, `id="exN"`, 예시 번호)을 쓰지 않는다.
- **언제**: 뜯어보기 표가 있는 핵심 display 식 하나당 1개. `generator`·`research`로 만드는 본문과 직접 호출에서 쓴다. 여러 식이 모인 모형은 목적식처럼 핵심인 곳에 1개만 둔다. 문장 속 기호와 단순한 제약식에는 쓰지 않는다.
- **간결하게**: 상황은 한두 문장, 뜻은 표 한 줄, 결론은 한 단락이다. ③ 표의 예시 값을 가능하면 그대로 쓴다. 가상 숫자면 "(자료 외 보충)"으로 밝힌다.
- **결론**: 결과값을 다시 읽는 데서 멈추지 않는다. 결정이나 입력 하나를 바꾸면 결과가 어떻게 달라지는지 계산해 식의 의미를 보여 준다. 비교의 전제("전환과 자투리가 같다고 보면")도 적는다.
- **숫자를 넣은 식**: 원래 식과 같은 `\class{tN}` 색을 쓴다. 폭이 넘치면 `aligned`로 두 줄로 나눈다.
- **숫자 말풍선**: 식과 표에 있는 입력 숫자마다 `\class{sv-키}{숫자}`로 감싼다. `.eq-sym`에 키별로 기호 SVG와 뜻, 단위를 적는다. 같은 숫자라도 다른 기호에 들어가면 키를 다르게 한다. 강조, 말풍선, 안내 문장은 `ta.py fragments`가 넣는 `eqlink.html`이 맡으므로 스크립트를 문서에 직접 넣지 않는다.

```html
<div class="eq-case" id="eq-case-N">
<p class="eq-case-h">수식 사례: 화이트 주문 800kg에 1,000kg을 만든 경우</p>
<p>상황 한두 문장.</p>
{숫자를 넣은 display 식 SVG: Z=\class{t1}{\class{sv-p}{2{,}500}\times \class{sv-s}{800}}-…}
<table class="eqx" id="eqx-K">
<tr><th>식에 넣은 숫자</th><th>뜻</th><th>금액 (원)</th></tr>
<tr class="t1"><td>{\class{sv-p}{2{,}500}\times \class{sv-s}{800} SVG}</td><td>납품한 800kg의 매출</td><td class="n">2,000,000</td></tr>
<tr class="combo"><td>{Z SVG}</td><td>이 스케줄의 점수</td><td class="n"><b>110,000</b></td></tr>
</table>
<p>결정이나 입력 하나를 바꾼 계산과 결론.</p>
<div class="eq-sym" hidden><span data-k="p">{p_i SVG} <b>판가</b> (원/kg)</span><span data-k="s">{s_i SVG} <b>판매량</b> (kg)</span></div>
</div>
```

## 여러 식이 모인 모형
- 먼저 4번 그리드로 모형 전체를 보여 준다.
- 그다음 줄마다 ③~⑤를 쓴다. 앞 줄에서 이미 푼 기호는 다시 행을 만들지 않고 그 표로 링크(`#eqx-N`)한다.
- 표·계산 블록에 `id="eqx-N"`을 붙여 본문에서 상호 참조할 수 있게 한다.

## 같은 기호가 다시 나올 때
- 처음 나온 곳에서만 풀이한다. 이후에는 inline SVG만 쓰고, 멀리 떨어져 있으면 처음 푼 표로 링크한다.

## 퀴즈 (`quiz`)
- 수식이 문서의 핵심이면 퀴즈 중 최소 1문항은 "이 항(또는 항의 조합)이 무슨 뜻인가"를 묻는다.

# 다른 ta 스킬에서 쓸 때
- **`generator`·`research`**: 본문을 쓸 때 위 표기·설명 규칙을 그대로 쓰고, 뜯어보기 표가 있는 핵심 식에는 "## 수식 사례"를 붙인다. 출처 표기(`.src`)는 식 블록이나 뜯어보기 표 바로 뒤 문장 끝에 단다.
- **supplement**: 보충에서 새 수식을 꺼내지 않는 원칙은 그대로다. 단, 막힌 부분이 수식이면 그 식을 inline·display SVG로 다시 보여 주고 ③~⑤를 **막힌 항 위주로** 쓴다. 숫자 대입(④)을 꼭 넣는다.
- **example**(`example` 규칙으로 쓰는 모든 예시): 예시에 식 대입이 들어가면 ④ 형식으로 쓰고, 예시 값을 바꾼 ③ 표를 짧게 붙여도 된다.
- **quiz**: 문항·보기·해설의 수식은 위 표기 규칙(SVG)을 따르되 `\class{tN}` 색은 쓰지 않는다("## 퀴즈" 참고).

# 직접 호출했을 때 (기존 학습자료 수식 고치기)
1. **대상 파일**: 인자 경로. 없으면 `ta.py config`의 `out_dir`(기본 `학습자료/`)에서 가장 최근 수정된 `*<suffix_notes>*.html`. 그것도 없으면 묻는다.
2. **수식 찾기**: `ta.py mathscan <파일>` — HTML 전체를 Read로 읽지 않는다(base64 이미지 때문). 아직 SVG(`class="m"`)로 안 바뀐 후보를 종류별로 돌려준다: `subsup`(`<sub>`/`<sup>`가 붙은 기호. 서수·단위 `m<sup>2</sup>`는 제외), `unicode`(Σ ∑ ∏ √ ≤ ≥ ≠ ≈ ∈ ∀ λ μ σ θ π 등), `mono`(monospace로 정렬한 식 블록). 각 후보는 블록 태그·`id`·원본 오프셋·본문을 담는다.
   - 사용자가 수식이나 위치를 지정했으면 그것만 고친다. 후보 중 비수식(화학식, 각주 번호)은 뺀다.
3. **백업**: `ta.py backup <파일>`.
4. **변환**: 수식을 LaTeX로 옮겨 SVG로 바꾼다. 원래 뜻을 바꾸지 않는다. 식 블록은 display나 그리드로, 문장 속 기호는 inline으로 바꾼다. 고칠 블록은 `mathscan`의 오프셋으로 원본 HTML을 잘라 읽고(`Read`가 아니라 Python 슬라이스), 바꾼 블록을 같은 자리에 써 넣는다.
5. **설명 보강**: 각 display 식에 위 설명 규칙(①~⑤) 중 빠진 것을 덧붙인다. 원래 문장은 지우지 않는다. 근거·출처 표기는 그 문서를 만든 스킬의 방식(`파일명 p.N` 또는 `[N]`)을 따른다.
6. **확인**: `ta.py fragments <파일>`로 `math.css`와 공용 조각을 맞추고, 아래 "작성 후 점검"을 하고, `open`으로 연다. 응답에는 파일 경로, 바꾼 수식 개수, 덧붙인 설명 블록만 적는다.

# 작성 후 점검
- `ta.py mathscan <파일>`을 다시 돌려 `<sub>`·유니코드로 흉내 낸 수식이 남아 있지 않은지 확인한다(단위나 화학식 같은 비수식 첨자는 제외).
- 수식 사례의 계산을 코드로 다시 확인하고, 입력 숫자마다 `sv-키`와 `.eq-sym` 항목이 짝지어져 있는지 본다. 숫자를 넣은 식이 가로로 넘치지 않는지 캡처로 본다.
- 뜯어보기 표의 기호마다 유래나 "줄임말 아님"이 적혀 있는지 확인한다.
- 뜯어보기 표가 있으면 `ta.py fragments <파일> --check`에서 `eqlink.html`이 `current`인지 보고, 표의 색 있는 줄이 식의 같은 항과 짝지어져 있는지 확인한다.
- 수식 블록을 문서 CSS와 함께 헤드리스 Chrome으로 라이트·다크 두 번 캡처해 직접 본다. Chrome이 없으면 스크립트가 건너뛴다고 알린다.
  ```bash
  python3 <ta.py> shot <파일> --id eqx-N --out <scratch>/eq.png
  python3 <ta.py> shot <파일> --id eqx-N --dark --out <scratch>/eq-dark.png
  python3 <ta.py> shot <파일> --id eqx-N --width 400 --out <scratch>/eq-m.png   # 모바일 폭
  ```
  식 블록에 `id`가 없으면 `--snippet <조각.html>`로 조각을 준다.
  - 볼 것: 글자 겹침·잘림, 색 짝짓기가 맞는지, 표 첫 칸 수식 크기, 모바일 폭에서 가로 넘침.
- ③ 표의 예시 값과 ④ 계산을 다시 계산해 맞는지 확인한다.
